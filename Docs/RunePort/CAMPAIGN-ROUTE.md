| TrialPit | CineInterpolationPoint15, tag Fallflic, Event NextLevel | TeleporterTriggered0 → BeetleFly/start |
| BeetleFly | TeleporterTriggered0, tag LoadThorapproachtele | ThorApproach/start |

`CineTrigger.TriggerAction` refuses to create a second CineCamera, spawns a camera, and starts the Event-tagged path. `CineCamera.StartCam` finds Position=0, optionally inserts temporary interpolation nodes, selects PHYS_Interpolating, and enters Interpolating. `CineInterpolationPoint.InterpolateEnd` fires its Event. The camera pauses through Timer/PauseTime and releases RunePlayer from Scripting at bEndOfPath. `TeleporterTriggered.Trigger` iterates players and calls original Teleporter.Touch, preserving its usual teleport guards. Directly invoking an exit only tests this final portion; it does not prove the preceding cinematic.

Recommended assertions: first point selected, point sequence advances, no duplicate cameras, pauses resume, endpoint event occurs once, destination map matches URL, and the player regains control at intended playable moments. Test the full opening without forcibly releasing its cinematic or jumping directly to exit tags.

## Required compatibility work and narrower evidence

- **Polyobj moving brushes:** original Engine.Polyobj extends Brush, not Mover. It has 16 KeyPos/KeyRot entries, per-segment MoveTime, and PolyObjGlideType. InterpolateTo sets PHYS_MovingBrush; its completion chains keys and fires InterpolateEvent. At audit start rendering, world bounds, collision, and moving-brush physics explicitly accepted only C++ UMover. RunePolyobj doors/platforms/destructible geometry therefore require a coherent shared path. Map presence alone does not prove every instance is mandatory.
- **Cinematic interpolation:** original InterpolationPoint exposes bInterpInstant and bSplineThruPoints. The starting engine ignored both, always choosing its spline when neighbors existed. Parent owns the correction and tests; no parity claim follows solely from adding fields.
- **Script synchronization:** ScriptPawn.Scripting handles ScriptAction/ScriptDispatcher bWaitToBeTriggered by setting WaitingScripter and calling WaitForRelease. ScriptAction.Trigger calls Release. Script points depend on ActorReachable/MoveToward or FindBestPathToward, then ArriveEvent and NextOrderTag. Verify wait/release ordering and navigation rather than skipping actions.
- **Underwater/Hel:** existing isolated save probe invokes original SinkingShip2.Teleporter0 → DeepUnder1Odin/Start and DeepUnder1Odin.Teleporter1 → DeepUnder3/Start. These are validated exit scripts, not traversed levels. New traversal must exercise waterline changes, breath/health, climbable vines/chains, doors/platforms, and Hel scripted sequences. Inventory classes identify coverage candidates; only an event/geometry walkthrough can establish which puzzle is mandatory.
